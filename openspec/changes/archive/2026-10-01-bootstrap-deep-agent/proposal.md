## Why

`open-assistant` 要从零搭一个「基于 subagents 的个人助手」，但完整的形态（子 agent、todo、cron、heartbeat、wiki、前端 UI）体量太大，无法一次性验证。当前没有任何可运行代码，也没有可验收的行为契约。

因此需要一个**最小可运行的 manager agent 基座**：先把「能对话、有人设、能读写文件、会话可恢复、长对话不爆上下文」这条主干打通并固化为行为契约，后续能力（todo / cron / heartbeat / wiki / 子 agent / 前端）在这个主干上逐层叠加。

## What Changes

- 新增一个可运行的 manager agent：单 agent、多轮对话、流式回复、工具调用可见
- 新增助手人设装配机制：从工作区的人设文件装载身份与行为准则，**每个会话生效**，文件缺失时回退内置默认人设
- 新增会话持久化：会话有稳定唯一标识、跨重启可恢复、可列举历史会话、会话之间数据相互隔离
- 新增上下文压缩：接近模型上下文上限时自动压缩较早历史并保留最近对话，被压缩内容仍可在持久化历史中检索
- 新增工作区目录：每个助手一块独立目录，作为所有文件操作的根；agent 文件操作被限制在目录内（含 `..` 与符号链接的穿越防护）；凭据类敏感数据存放在工作区之外
- 新增助手工作区文件操作能力：读取 / 创建 / 修改 / 列举工作区内文件
- 新增对话界面契约：助手回合的结构化呈现（思考 / 工具调用 / 结论分层）、思考过程可见且不混入答复、**工具调用按类型专门呈现**（文件类工具摘要行必须显示路径，改动展示为增删对照）、工具三态可见、**全中文界面**
- 新增工作区界面：**右侧可拖拽工作区侧边栏** + 懒加载文件树 + 按文件类型分流渲染（JSON 结构化、Markdown 富文本、代码高亮、图片、纯文本、不支持时给提示）
- 新增 TODO 专用视图：在工作区中打开 TODO 文件时进入待办视图，按状态分组、可在界面内修改
- 新增 TODO 持久化契约：**以单个 JSON 文件为唯一事实源**，人和 agent 都可读写，向 agent 提供增删改查工具，并发写入不互相覆盖
- 变更：**工作区与对话强绑定** —— 未指定工作区不得开始对话；会话数据落在所属工作区目录内，且会话列表按工作区隔离
- 新增应用外壳：**左导航 + 顶部栏 + 内容区**的常驻壳层、**多页面路由**（可刷新/可回退/可分享）、**可停靠侧边面板**（能拖出浮动也能吸附回边，换形态不重建内容）、**导航条目可配置**（排序与显隐，核心条目固定）、**扩展插槽**与**页面级故障隔离**
- 变更：工作区侧边栏升级为**可停靠工作区面板**（可在对话区一侧停靠，也可拖出浮动）
- 新增：对话区**宽窄模式**切换（选择被记住）

**非目标（本变更明确不做，留待后续变更）**：子 agent 与委派、cron 定时任务、heartbeat、wiki 与长期记忆、多用户与鉴权、人工审批（HITL）的完整流程、文件的新建/重命名/删除（本条除外：TODO 文件本身可改）、云端部署。

## Capabilities

### New Capabilities

- `agent-core`: 助手 agent 的对话循环、流式回复、人设装载、工作区文件操作与工具调用可见性
- `session-store`: 会话的持久化、稳定标识与隔离、历史列举、按工作区归属与检索、上下文压缩及压缩内容的可回溯性
- `workspace`: 助手工作区目录的定义、文件操作的路径约束、人设文件保护、敏感信息分离，以及与对话的强绑定
- `chat-ui`: 对话界面的呈现契约——中文界面、助手回合的结构化分层、思考过程展示、工具调用按类型专门呈现与三态可见
- `file-workspace-ui`: 右侧工作区侧边栏、文件树、按文件类型分流渲染、TODO 专用视图与改动可见性
- `todo-store`: TODO 的 JSON 持久化契约——条目字段、agent 读写工具、并发写入安全
- `app-shell`: 应用外壳——左导航/顶部栏/内容区的常驻结构、多页面路由、可停靠侧边面板、导航条目可配置、扩展插槽与页面级故障隔离

### Modified Capabilities

（无。本项目此前没有已存在的 capability。）

## Impact

- **代码**：全新代码库。需要建立后端 TypeScript 工程骨架（agent 运行时、会话存储、工作区管理）与终端交互入口
- **依赖**：新增 agent 运行时、会话持久化与流式传输相关依赖；具体选型见后续 design.md
- **数据**：新增本地持久化数据 —— 会话与执行状态、上下文历史、工作区目录内容。首次运行时创建
- **配置**：新增工作区路径、凭据路径、上下文压缩阈值等配置项
- **破坏性变更**：无（全新项目）
- **风险**：上下文压缩策略若实现不当会造成历史静默丢失，故将「压缩不静默丢失」写为硬性要求
