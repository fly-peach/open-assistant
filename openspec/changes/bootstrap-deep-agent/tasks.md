## 8. 工作区改为「用户本机路径」（优化）

> 背景：原设计是服务端在 `WORKSPACE_ROOT` 下自建 id 目录，用户无法指向自己的文件夹。改为
> **用户在本机文件系统中选择/新建一个目录作为工作区**。详见 design.md Decision #3。

- [x] 8.1 后端：把工作区解析从「id → 目录」改为「绝对路径 → 目录」，并用测试断言绝对路径、相对路径、不存在的路径各自的处理（对齐 `workspace`：用户选择本机目录）
- [x] 8.2 后端：实现路径校验（存在或可创建 / 是目录 / 可读写）并返回可读错误，用测试覆盖每种非法输入
- [x] 8.3 后端：拒绝文件系统根（`C:\`、`/` 及盘符根），并用测试断言被拒且错误可读（对齐 `workspace`：拒绝文件系统根目录）
- [x] 8.4 后端：用 `realpath` 归一化后判重，用测试断言同一目录的不同写法（大小写 / 尾斜杠 / 相对符号）被识别为同一工作区
- [x] 8.5 后端：目录浏览接口（无参列磁盘/根；给定路径列其子目录；只列目录；无权限时给提示不整体失败），并用测试覆盖三种情况（对齐 `workspace`：本机目录浏览与选择）
- [x] 8.6 后端：应用数据（会话索引/配置）改到 `<工作区>/.open-assistant/`，并用测试断言不会写到工作区根（对齐 `session-store`：会话数据在工作区内的应用数据子目录）
- [x] 8.7 后端：目录非空时不生成骨架（只为空时生成），并用测试断言非空目录内容一个字节都没变（对齐 `workspace`：仅在目录为空时生成骨架）
- [x] 8.8 后端：HTTP 路由从 `:id` 改为以路径为参数（需处理好路径转义/编码），并用 curl 断言各端点可用
- [x] 8.9 前端：工作区选择器改为「本机目录选择器」（可从磁盘根逐层浏览、可直接输入绝对路径、可新建目录），并用 browser-use 实测选择流程（对齐 `file-workspace-ui`：通过本机目录选择器指定工作区）
- [x] 8.10 前端：侧边栏与选择器展示工作区的**完整绝对路径**，并用 browser-use 断言可见（对齐 `file-workspace-ui`：展示当前工作区的完整路径）
- [x] 8.11 前端：路径过长时的展示（中间省略 + hover 看全文），并用 browser-use 断言不撑破布局
- [x] 8.12 迁移验证：旧 id 工作区（`apps/server/.workspaces/*`）作为绝对路径仍可选用，断言能用其路径打开且文件树正常
